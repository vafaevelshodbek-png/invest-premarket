## Базовый способ и набор (№36)

**Базовый способ:** та же сверка SQL, правила известных причин и полнотекстовый поиск документов по номеру операции и ISIN. Специалист получает найденные документы без объяснения.

**Набор:** 30-50 закрытых расхождений от партнёра-брокера с известной причиной, подтверждённой специалистом. Обезличивание сохраняет связи между строками, операциями и документами. Типы: незавершённые расчёты, корпоративное действие, разница дат отражения, ошибка ключа, дубль, случаи без документов.

**Если партнёра нет.** Синтетический набор проверяет только код сверки и правил, но не роль AI. Это нужно прямо указать.

<a name="experiment"></a>

## Первый эксперимент (№25)

| Пункт | Содержание |
|---|---|
| Гипотеза | После правил остаются расхождения, для которых LLM по документам предлагает верную причину чаще, чем специалист находит её по результатам поиска |
| Данные | 30-50 закрытых обезличенных расхождений партнёра с известной причиной |
| Базовый способ | Сверка, правила и поиск документов без LLM |
| Метрика | Доля расхождений, для которых система указала верную причину с подтверждающим документом либо верно сообщила о нехватке данных |
| Порог | Не ниже 70% и не меньше чем на 15 процентных пунктов выше базового способа. Порог является предложением и согласуется со специалистом сверки |

Если базовый способ уже закрывает почти все случаи, AI не нужен и продукт сводится к обычной автоматизации.

<a name="risks"></a>

## Стоп-факторы (№26)

| Риск | Почему критично | Ранняя проверка |
|---|---|---|
| Нет доступа к данным | Без выгрузок и закрытых случаев продукт не проверить | Найти партнёра-брокера, согласовать обезличенный набор |
| Нет задачи для AI | Если правила закрывают почти всё, LLM лишняя | Посчитать долю расхождений без причины после правил на данных партнёра |
| Ложное объяснение | Ведёт к необоснованной корректировке учёта клиента | Проверка на закрытых случаях, обязательное подтверждение специалиста |
| Конкуренты | Duco и SmartStream уже заявляют агентный разбор исключений | Узнать, какими системами пользуются российские брокеры |
| Интеграция и конфиденциальность | Данные клиентов нельзя вывести наружу, интеграция с бэк-офисом дорогая | Вопрос ИБ и владельцу бэк-офиса партнёра |
