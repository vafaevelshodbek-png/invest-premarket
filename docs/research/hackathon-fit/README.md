# Какие идеи подходят хакатону Т-Банка

Исследование от 11 ноября 2026 года для выбора идеи в [№2](https://github.com/vafaevelshodbek-png/invest-premarket/issues/2). Подготовлено AI-ассистентом по запросу участника команды, источники открыты 11 ноября 2026 года. Интервью и запусков продуктов не было. Оценки идей являются предложением, выбор делает команда.

## Главное

1. **Организаторы ищут сценарии на инфраструктуре Т-Банка и MCP, «которых пока нет на рынке».** Прежние кандидаты A и B этой инфраструктуры не используют ([анонс](#s1)).
2. **Простые сценарии уже показал сам Т-Банк.** В официальной статье про MCP описана «лестница»: информационный ассистент, сводки по расписанию, алерты, ребалансировка, робот с подтверждением ([S2](#s2)). В приложении уже есть календарь оферт и погашений с напоминаниями ([S3](#s3)). Идеи «ассистент по портфелю» и «напоминания о событиях» новизны не дают.
3. **Подбор портфеля под цель упирается в регулирование.** Индивидуальные инвестиционные рекомендации через программу требуют аккредитации в НАУФОР или СРО НФА, у Т-Банка уже есть аккредитованный робо-эдвайзер ([S7](#s7)).
4. **Самая заметная незакрытая проблема: защита частного инвестора от ошибок перед сделкой.** Средняя доходность частных инвесторов за 2023-2025 годы составила около 2,9% годовых, и 41% получили меньше доходности индекса гособлигаций ([S8](#s8)). Технических дефолтов по облигациям в 2025 году стало втрое больше ([S9](#s9)). Манипуляции через Telegram-каналы расследуются в 2026 году, а Банк России готовит регулирование финансовых инфлюенсеров ([S10](#s10)).
5. **В Т-Банке есть естественная точка встраивания: каждая операция через MCP требует подтверждения клиента** ([S1](#s1)). Проверка сделки перед подтверждением пока нигде не описана как продукт.

## Что даёт API для новых идей

По официальным контрактам API ([S6](#s6)), прочитанным 11 ноября 2026 года:

| Данные | Методы и поля |
|---|---|
| События облигаций | `GetBondEvents`: купон, оферта, погашение, конвертация, даты фиксации и выплаты, цена выкупа, дата дефолта |
| Особенности облигации | Флаги амортизации, плавающего купона, бессрочности, субординации, только для квалифицированных, уровень риска |
| Отчётность и аналитика | `GetAssetReports` (календарь отчётности), `GetAssetFundamentals`, `GetConsensusForecasts`, `GetForecastBy` |
| Сделки инсайдеров | `GetInsiderDeals` |
| Сигналы и стратегии | `GetStrategies`, `GetSignals` |
| Рынок и счёт | Свечи, стакан, сделки, портфель, операции, предварительная стоимость заявки, песочница |

Наличие метода не подтверждает покрытие всех бумаг и доступ конкретного токена. В песочнице купоны и дивиденды не начисляются ([разбор API](../invest-api/README.md)).

## Ограничения для любой идеи

- **Рекомендация.** Агент объясняет последствия и риски, но не говорит «купи» или «продай». Иначе это индивидуальная рекомендация с аккредитацией ([S7](#s7)). Т-Инвестиции и Robinhood так же маркируют выводы агентов ([S1](#s1), [S17](#s17)).
- **Подтверждение.** Любое действие со счётом подтверждает клиент ([S1](#s1)).
- **Данные.** Работаем от имени клиента и с его токеном, ретрансляция данных API ограничена ([разбор API](../invest-api/README.md)).

## Оценка идей

Оценка от 1 до 3 по критериям: попадание в номинацию, Т-Банк и MCP, новизна, MVP за 10 дней, AI по делу, проверяемость.

| Идея | Номинация | Сумма | Почему |
|---|---|---|---|
| **1. Второе мнение перед сделкой.** Перед подтверждением заявки агент проверяет её в контексте клиента: события и особенности облигации, признаки разгона бумаги (аномальный объём и цена, сделки инсайдеров), ближайшую отчётность эмитента, концентрацию портфеля, налоговые последствия продажи. Объясняет простыми словами, решение за клиентом | AI-агент, Гран-при | **17** | Новизна: аналогов не найдено. Встраивается ровно в обязательный шаг подтверждения MCP. Ценность для Т-Банка: меньше убытков и жалоб клиентов, совпадает с фокусом регулятора на защите розницы. Данные есть в API |
| **2. Фактчекер инвестиционного сигнала.** Клиент присылает пост из Telegram или Пульса, агент выделяет утверждения и проверяет их по данным: цена, объём, отчётность, раскрытия. Помечает признаки разгона | AI-агент или новый опыт | **16** | AI нужен по делу: утверждения в свободном тексте. Проверяемо на публичных кейсах манипуляций с известными бумагами и датами. Может быть модулем идеи 1 |
| 3. Помощник по событиям облигаций. Объясняет экономику оферты, амортизации, конвертации для позиции клиента и готовит действие | AI-агент | 14 | Напоминания уже есть в приложении, новизна только в объяснении и подготовке действия |
| 4. Объяснимый робот для автоследования. Стратегия публикует сигналы в автоследование и объясняет каждую сделку, честно показывает доходность после издержек | AI-робот | 14 | Попадает в номинацию робота и продукт Т-Банка. Риск: качество стратегии нельзя честно доказать за 10 дней |
| 5. Стратегия словами в робота | AI-робот | 13 | Есть ZipLime у Финама, новизна ниже |
| 6. Сторож портфеля (сводки и алерты) | AI-агент | 12 | Совпадает с примерами Т-Банка и Robinhood |
| 7. Портфель под цель | AI-агент | 10 | Регулирование робо-эдвайзинга, у Т-Банка есть свой |

**Предложение:** основная идея 1, а идея 2 входит в неё как модуль проверки «откуда идея сделки». Запасные концепции для очного этапа: 3 и 4. Наработки по кандидату A переносятся в разбор отчётности эмитента внутри идеи 1.

## Что проверить до выбора

- Есть ли у участников команды личный опыт сделок, о которых потом жалели. Это лучшее основание для поля 3.
- Даёт ли токен песочницы рыночные данные и события облигаций. Если нет, для демо нужен токен только на чтение.
- Какие кейсы манипуляций Банк России опубликовал с названиями бумаг и датами. Это набор для эксперимента идеи 2.
