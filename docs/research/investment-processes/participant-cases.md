# Рабочие ситуации участников

[Краткое саммари](participants-summary.md) · [Все процессы и роли](participants.md) · [Исходная карта](details.md)

Каждая карточка описывает одного главного пользователя в заданной организации и услуге. Другие люди названы как поставщики входов, принимающие решение, проверяющие или получатели. Пользователь, получатель пользы и возможный покупатель разделены.

**Статус всех 16 ситуаций: модель.** Документы подтверждают операции и некоторые границы функций, но не фактическую работу конкретной компании. Частота, последствия ошибок и покупатель являются гипотезами. Числовые оценки не придуманы.

Для дальнейшего сравнения ситуаций можно использовать публичные регламенты, документацию и описания существующих продуктов. Реальные случаи и интервью помогут дополнительно проверить предположения о работе людей.

Основные процессы создают результат главного пользователя. Смежные дают вход, статус или принимают передачу, их собственная работа этим не считается изученной. Условия и исключения разъяснены в карточке.

| Ситуация | Главный результат |
|---|---|
| [1. Инвестор сравнивает облигации](#bonds) | Сравнение с источниками, датами и допущениями, затем решение с параметрами или отказ |
| [2. Аналитик пересматривает оценку после раскрытия](#disclosure) | Записка о подтверждённых изменениях и затронутых выводах |
| [3. Управляющий пересматривает портфель](#portfolio) | Проверяемое состояние портфеля и решение с основанием |
| [4. Трейдер брокера сопровождает частичное исполнение](#execution) | Согласованные исполненная часть, остаток и статус, основание изменения или отмены |
| [5. Специалист депозитария передаёт волеизъявление](#corporate-action) | Инструкция с подтверждением приёма или отказом и последующим статусом |
| [6. Поддержка брокера выясняет статус купона](#payment) | Обоснованный ответ и при необходимости адресная эскалация |
| [7. Специалист брокера разбирает расхождение учёта](#reconciliation) | Перечень различий с причинами, а для закрытых различий основания исправлений и повторная сверка. |
| [8. Казначей покрывает потребность в обеспечении](#collateral) | План покрытия, разрешённые распоряжения и подтверждения либо непокрытая потребность с эскалацией. |
| [9. Сотрудник УК сопровождает погашение пая](#fund-redemption) | Связанный комплект заявки и подтверждённых статусов погашения и выплаты либо обоснованного отказа |
| [10. Специалист качества разбирает спорную цену](#data-quality) | Карточка дефекта или подтверждённое допустимое состояние, решение о пригодности и результат повторной проверки. |
| [11. Риск-менеджер разбирает превышение ограничения](#risk-breach) | Подтверждённое отклонение или обоснованное снятие сигнала с исходными данными |
| [12. Специалист брокера проверяет допуск к операции](#access) | Обоснованный статус доступа или запрос недостающего подтверждения |
| [13. Контролёр разбирает несоответствие операции](#control) | Вывод с основанием, ответственный за меру и статус устранения |
| [14. Инженер восстанавливает поток операций](#systems) | Восстановленный поток, проверенное окно событий, известные ограничения и материалы приёмки |
| [15. Специалист УК рассчитывает стоимость имущества фонда](#fund-valuation) | Расчёт стоимости чистых активов и расчётной стоимости пая с основаниями и статусом проверки |
| [16. Расчётный специалист устраняет несовпадение инструкций](#matching) | Исправленная по подтверждённому основанию инструкция и согласованный статус либо открытый вопрос с причиной |

## 1. Инвестор сравнивает облигации

| Поле | Содержание |
|---|---|
| Область | Облигации, вторичный рынок. Самостоятельный частный инвестор, клиент брокера. |
| Роль | Сам инвестор. Профессиональный аналитик является другим пользователем и разобран отдельно. |
| Ситуация | Появились свободные деньги на заданный срок, рассматриваются несколько выпусков. |
| Задача | Отбирает документы, сверяет даты и формулы денежных потоков, сопоставляет варианты с целью и расходами, отмечает неизвестное и принимает решение. |
| Текущий процесс | **Основные:** [Собрать сведения для конкретного решения](details.md#p02), [Оценить инструмент и варианты портфеля](details.md#p03), [Выбрать действие и параметры](details.md#p04). |
| Вход | Цель, срок, ограничения, версии документов выпусков, котировки на сопоставимый момент и расходы. |
| Результат | Сравнение с источниками, датами и допущениями, затем решение с параметрами или отказ. Условия проверяются по документам каждого выпуска. |
| Получатель | Сам инвестор. При покупке брокер получает отдельное поручение, а не аналитическую таблицу. |
| Полномочия и системы | Инвестор принимает решение. Брокер проверяет и исполняет последующее поручение. Сервис сравнения не получает полномочий распоряжаться деньгами. |
| Частота: гипотеза | Гипотеза: при размещении денег или пересмотре выбора. Число сравнений в месяц неизвестно. |
| Цена ошибки: гипотеза | Гипотеза: неподходящий денежный поток и расходы досрочного выхода. Нужны пример неверного вывода и время его обнаружения и исправления. |
| Покупка: гипотеза | Сам инвестор либо брокер как поставщик функции. Готовность платить и бюджет не установлены. |
| Основание и статус | [Документы и оценки в карте](details.md#p03). Метод сравнения и роль инвестора являются моделью, готового реального сравнения нет. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Недавний реальный выбор инвестора, документы нескольких выпусков и объяснение итога. Публичные документы позволяют проверить условия, но не спрос. |

## 2. Аналитик пересматривает оценку после раскрытия

| Поле | Содержание |
|---|---|
| Область | Акции или облигации одного эмитента. Аналитическая функция УК. |
| Роль | Аналитик эмитента, готовящий заключение управляющему. Не частный инвестор и не сотрудник эмитента. |
| Ситуация | Опубликован новый отчёт эмитента, который может изменить прежнюю оценку. |
| Задача | Сопоставляет раскрытие с предыдущей версией и своей моделью, проверяет изменившиеся предпосылки, пересчитывает затронутое и объясняет неопределённость. |
| Текущий процесс | **Основные:** [Собрать сведения для конкретного решения](details.md#p02), [Оценить инструмент и варианты портфеля](details.md#p03). **Смежные:** [Выбрать действие и параметры](details.md#p04). |
| Вход | Две версии раскрытия, прежняя оценка, данные об инструменте, запрос и ограничения управляющего. |
| Результат | Записка о подтверждённых изменениях и затронутых выводах. Каждое изменение прослеживается до документа или расчёта. |
| Получатель | Управляющий решает, нужно ли менять позицию. Выбор действия является следующим процессом. |
| Полномочия и системы | Аналитик отвечает за основание оценки, управляющий за решение в своих полномочиях. Система может помогать искать изменения, но её наличие не предполагается. |
| Частота: гипотеза | Гипотеза: по новым раскрытиям и запросам управляющего. Объём покрываемых эмитентов и число разборов неизвестны. |
| Цена ошибки: гипотеза | Гипотеза: пропуск существенного изменения или ненужный пересмотр. Нужны фактическое последствие и трудозатраты повторного анализа. |
| Покупка: гипотеза | УК через владельца аналитической функции. Инициатор и согласующий расходы пока неизвестны. |
| Основание и статус | [Подготовка оценки в карте](details.md#p03). Организационная схема и последовательность работы являются моделью. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Один завершённый разбор с исходными документами и запиской аналитика. Без доступа к аналитику это только проверка текста документов. |

## 3. Управляющий пересматривает портфель

| Поле | Содержание |
|---|---|
| Область | Портфель клиента по конкретному договору доверительного управления. |
| Роль | Управляющий портфелем. Аналитик поставляет оценки, риск-менеджер проверяет риск в своей функции. |
| Ситуация | После движения цен или денежных потоков выявлено отклонение от ограничений портфеля. |
| Задача | Проверяет состояние на дату, объясняет отклонение, сравнивает действия с расходами и ограничениями, фиксирует решение или сохранение позиции. |
| Текущий процесс | **Основные:** [Оценить текущее состояние портфеля](details.md#p14), [Выбрать действие и параметры](details.md#p04). **Смежные:** [Определить цели и ограничения](details.md#p01), [Оценка и ограничение рисков](details.md#s01). |
| Вход | Сверенные позиции и потоки, цены с датами, согласованный профиль, ограничения и оценки вариантов. |
| Результат | Проверяемое состояние портфеля и решение с основанием. Принятые параметры можно сопоставить с действующими ограничениями. |
| Получатель | Исполнение получает параметры при необходимости сделки, риск-менеджер сведения для своего контроля. |
| Полномочия и системы | Решение принимает управляющий в рамках договора. Риск-менеджер не выбирает вложение вместо него. Полномочия клиента определяются выбранной услугой. |
| Частота: гипотеза | Гипотеза: по установленному пересмотру или событию. Регламент и число пересмотров не установлены. |
| Цена ошибки: гипотеза | Гипотеза: действие на неверной позиции или вне ограничений. Нужны величина отклонения, задержка и фактическое исправление. |
| Покупка: гипотеза | Организация, оказывающая доверительное управление, через владельца инвестиционного процесса. Бюджет не подтверждён. |
| Основание и статус | [Стандарт управляющего](https://www.cbr.ru/Queries/XsltBlock/File/62016/72), главы 2–4, подтверждает профиль и риск. Рабочая ситуация модельная, на все фонды не переносится. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Обезличенный пересмотр с ограничениями, исходным состоянием и решением, включая допустимый вариант ничего не менять. |

<a name="execution"></a>

## 4. Трейдер брокера сопровождает частичное исполнение

| Поле | Содержание |
|---|---|
| Область | Вторичная торговля бумагой. Исполнение клиентского поручения у брокера. |
| Роль | Трейдер исполнения брокера. Самостоятельная торговля частного клиента является другой ситуацией. |
| Ситуация | Принятое поручение исполнено частично, сохраняются остаток и срок действия. |
| Задача | Связывает поручение, заявки и сделки, проверяет остаток и состояние, определяет допустимое дальнейшее действие по условиям поручения. |
| Текущий процесс | **Основные:** [Заключить сделку и обработать состояние поручения](details.md#p07). **Смежные:** [Оформить, зарегистрировать и проверить конкретное поручение](details.md#p05). |
| Вход | Принятое поручение, история заявок и статусов, сделки с временем и объёмом, релевантные рыночные сведения. |
| Результат | Согласованные исполненная часть, остаток и статус, основание изменения или отмены. Объёмы сверяются с историей сделок. |
| Получатель | Клиент получает статус, учёт и расчёты сведения по заключённым сделкам. |
| Полномочия и системы | Условия задаёт клиент, трейдер действует в предоставленных пределах. Обычные статусы обрабатывает система, предмет человеческой работы здесь исключение или проверка. |
| Частота: гипотеза | Гипотеза: по частичным исполнениям и исключениям. Доля поручений, требующих человека, неизвестна. |
| Цена ошибки: гипотеза | Гипотеза: лишняя операция или неверный остаток. Нужны пример, затронутый объём и время исправления. |
| Покупка: гипотеза | Брокер через владельца исполнения. Наличие стандартной функции терминала и потребность в дополнении проверяются в №32. |
| Основание и статус | [Стандарт брокера](https://www.cbr.ru/Queries/XsltBlock/File/62016/70), раздел 2, задаёт условия исполнения. Конкретная должность и ручные действия являются моделью. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Обезличенная история одного поручения с известным итогом. Измерение качества исполнения и доходности в этой ситуации не разобрано. |

## 5. Специалист депозитария передаёт волеизъявление

| Поле | Содержание |
|---|---|
| Область | Добровольный выкуп бумаги. Депозитарий в цепочке номинальных держателей. |
| Роль | Специалист корпоративных действий депозитария. |
| Ситуация | Получено уведомление о выкупе с вариантами участия и сроком инструкции. |
| Задача | Проверяет применимость и срок своего звена, получает решение уполномоченного владельца, проверяет и передаёт инструкцию, отслеживает статус. |
| Текущий процесс | **Основные:** [Направить волеизъявление по корпоративному действию](details.md#p18). **Смежные:** [Зафиксировать права и движения по бумагам](details.md#p11). |
| Вход | Версия уведомления, подтверждённые права, варианты, сроки, полномочия и решение владельца. |
| Результат | Инструкция с подтверждением приёма или отказом и последующим статусом. Идентификаторы и сроки согласуются с документами события. |
| Получатель | Следующее звено учётной цепочки принимает инструкцию, владелец получает статус участия. |
| Полномочия и системы | Вариант выбирает владелец или уполномоченный управляющий. Посредник передаёт волеизъявление и разбирает исключения, не выбирает за владельца. |
| Частота: гипотеза | Гипотеза: по событиям в обслуживаемых позициях. Число событий и срочных исключений неизвестно. |
| Цена ошибки: гипотеза | Гипотеза: пропуск участия или неверное волеизъявление. Нужны сроки звеньев и завершённый случай с известным последствием. |
| Покупка: гипотеза | Депозитарий через владельца обслуживания активов. Пользователь и бюджетный согласующий могут различаться. |
| Основание и статус | [Уведомления и сроки НРД](https://www.nsd.ru/services/depozitariy/obsluzhivanie-aktivov/sodeystvie-realizatsii-prav-po-tsennym-bumagam/informirovanie-po-korporativnym-deystviyam/). Обязанности конкретного сотрудника моделируются. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Публичное уведомление и обезличенная цепочка инструкции с итоговым статусом. Один календарь не подтверждает участие. |

## 6. Поддержка брокера выясняет статус купона

| Поле | Содержание |
|---|---|
| Область | Купон по облигации на счёте клиента брокера. |
| Роль | Специалист поддержки брокера с разрешённым доступом к клиентским документам. |
| Ситуация | Клиент сообщает, что ожидаемый купон не появился на счёте. |
| Задача | Идентифицирует событие, сопоставляет ожидание и разрешённые записи, отделяет подтверждённое от неизвестного, направляет конкретный вопрос исполнителю выплат или сверки. |
| Текущий процесс | **Основные:** [Информация и обращения](details.md#s10). **Смежные:** [Обработать выплаты и обязательные изменения прав](details.md#p17), [Сформировать и передать отчет клиенту](details.md#p21), [Сопоставить внутренние и внешние записи](details.md#p13). |
| Вход | Обращение, событие, позиции и документы счёта, сведения о фактических движениях и применимых удержаниях. |
| Результат | Обоснованный ответ и при необходимости адресная эскалация. Статус проверяется по фактическим документам, неизвестное остаётся открытым. |
| Получатель | Клиент получает ответ, специалист выплат или сверки получает конкретное расхождение и материалы. |
| Полномочия и системы | Поддержка объясняет и эскалирует. Выплату и исправление учёта выполняют другие уполномоченные роли. Сверка нужна только при соответствующем расхождении. |
| Частота: гипотеза | Гипотеза: по обращениям о выплатах. Число обращений и повторных контактов неизвестно. |
| Цена ошибки: гипотеза | Гипотеза: неверный ответ, повторное обращение или пропуск проблемы. Нужны время разбора, число эскалаций и итоговая причина. |
| Покупка: гипотеза | Брокер через владельца поддержки. Готовность выделить бюджет и правила доступа не установлены. |
| Основание и статус | [Выплаты НРД](https://www.nsd.ru/services/depozitariy/obsluzhivanie-aktivov/sodeystvie-realizatsii-prav-po-tsennym-bumagam/vyplata-dokhodov-po-tsennym-bumagam/) подтверждают операции с депонентами. Процедура поддержки является моделью. **Рабочая ситуация: модель.** |

| Роль | Инженер эксплуатации соответствующего сервиса. Операционный потребитель подтверждает полноту бизнес-записей. |
| Ситуация | Мониторинг или пользователь сообщил, что поток операций перестал поступать. |
| Задача | Локализует сбой, восстанавливает обмен, устанавливает окно пропуска, сопровождает разрешённое восстановление записей и передаёт потребителю результаты проверки. |
| Текущий процесс | **Основные:** [Работоспособность систем и восстановление после сбоев](details.md#s13). **Смежные:** [Снабжение данными](details.md#s11), [Отразить операции у профучастника](details.md#p12), [Сопоставить внутренние и внешние записи](details.md#p13). |
| Вход | Сигнал, журналы и состояние интеграции, последнее подтверждённое событие, правила повторной обработки. |
| Результат | Восстановленный поток, проверенное окно событий, известные ограничения и материалы приёмки. Одного успешного соединения недостаточно. |
| Получатель | Владелец сервиса принимает техническое восстановление, специалист учёта или сверки подтверждает полноту и отсутствие недопустимых повторов. |
| Полномочия и системы | Инженер восстанавливает сервис по своим полномочиям, не объявляет финансовую запись верной без операционной проверки. Расследование угрозы ИБ является другим процессом. |
| Частота: гипотеза | Гипотеза: по сбоям и деградациям. Частота, время восстановления и объём ручной проверки неизвестны. |
| Цена ошибки: гипотеза | Гипотеза: потерянные или повторные записи. Нужны окно сбоя, затронутые операции и время подтверждения восстановления. |
| Покупка: гипотеза | Брокер через владельца ИТ-сервиса или эксплуатации. Состав существующих средств мониторинга проверяется в №32. |
| Основание и статус | [Рекомендации Банка России по операционному риску](https://www.cbr.ru/Crosscut/LawActs/File/9909), адресаты и организация процесса, плюс [карта восстановления](details.md#s13). Техническая последовательность модельная. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Обезличенный закрытый инцидент с журналами и операционной приёмкой. Учебный сбой без реального пользователя не подтверждает спрос. |

## 15. Специалист УК рассчитывает стоимость имущества фонда

| Поле | Содержание |
|---|---|
| Область | Один ПИФ, одна дата оценки и применимые правила определения стоимости. |
| Роль | Специалист расчёта стоимости в УК. Спецдепозитарий выполняет свою контрольную функцию. |
| Ситуация | Наступила установленная для выбранного фонда дата расчёта. |
| Задача | Проверяет состав имущества и обязательств, применяет допустимые оценки, связывает расчёт с числом паёв, выделяет несогласованные сведения и передаёт результат на проверку. |
| Текущий процесс | **Основные:** [Оценить имущество и обязательства фонда](details.md#p24). **Смежные:** [Контроль специализированного депозитария](details.md#s07), [Сопоставить внутренние и внешние записи](details.md#p13). |
| Вход | Сверенные активы и обязательства, цены и основания оценок, число паёв, правила фонда и даты. |
| Результат | Расчёт стоимости чистых активов и расчётной стоимости пая с основаниями и статусом проверки. Биржевая цена пая не используется как замена результата. |
| Получатель | Предусмотренный проверяющий, контролёр спецдепозитария и специалист операций с паями получают относящиеся к ним сведения. |
| Полномочия и системы | Расчёт, контроль и операции с паями разделены. Конкретная методика, согласования и периодичность определяются выбранным фондом. |
| Частота: гипотеза | Гипотеза: по установленным датам оценки. Частота исключений и трудозатраты неизвестны. |
| Цена ошибки: гипотеза | Гипотеза: неверная стоимость и последующий пересчёт. Нужны затронутые операции и фактические расходы исправления. |
| Покупка: гипотеза | УК через владельца расчёта стоимости. Контролёр спецдепозитария может быть отдельным пользователем другого решения. |
| Основание и статус | [Оценка фонда и источники карты](details.md#p24), [участники Платформы ПИФ](https://www.nsd.ru/services/depozitariy/kollektivnie-investitsii/kollektivnye-investitsii-v-nrd/). Распределение рабочих действий модельное. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Обезличенный законченный расчёт одной даты с исходными данными, правилами и результатом проверки. Не воспроизводит все виды фондов. |

## 16. Расчётный специалист устраняет несовпадение инструкций

| Поле | Содержание |
|---|---|
| Область | Внебиржевая сделка с бумагами, расчёты через НРД с применимым электронным мэтчингом. |
| Роль | Расчётный специалист стороны сделки, обрабатывающий несовпадение. Специалист другой стороны действует в своих полномочиях. |
| Ситуация | Получено сообщение о потенциальных встречных инструкциях с разными параметрами, например датой расчёта. |
| Задача | Сверяет различающееся поле с условиями сделки, устанавливает основание корректного значения, согласует допустимое исправление и проверяет статус повторной обработки. |
| Текущий процесс | **Основные:** [Подтвердить параметры и согласовать расчетные инструкции](details.md#p08). **Смежные:** [Заключить сделку и обработать состояние поручения](details.md#p07), [Исполнить денежные и поставочные обязательства](details.md#p10). |
| Вход | Согласованные условия сделки, две инструкции, сообщение о несовпадении и применимые правила расчёта. |
| Результат | Исправленная по подтверждённому основанию инструкция и согласованный статус либо открытый вопрос с причиной. Само движение активов ещё не считается выполненным. |
| Получатель | Исполнитель расчётов получает согласованные инструкции, учёт и другая сторона подтверждённый статус. |
| Полномочия и системы | Система выявляет потенциальное соответствие. Специалист не меняет существенные условия сделки произвольно и не подменяет заключение сделки или окончательную сверку остатков. |
| Частота: гипотеза | Гипотеза: по сообщениям о несовпадениях. Число инструкций и доля ручных разборов неизвестны. |
| Цена ошибки: гипотеза | Гипотеза: задержка расчётов или исправление неверного поля. Нужны фактическое окно задержки и история согласованного исправления. |
| Покупка: гипотеза | Участник расчётов через владельца операций. Потребность в дополнении к действующему мэтчингу не подтверждена. |
| Основание и статус | [Электронный мэтчинг НРД](https://www.nsd.ru/services/depozitariy/operatsii-s-tsennymi-bumagami/vnebirzhevye-raschety/elektronnyy-metching/), описание и различающиеся поля. Действия сотрудника моделируются. **Рабочая ситуация: модель.** |
| Дополнительная проверка | Обезличенные инструкции, сообщение и известная причина расхождения. Сначала проверяется, что именно уже делает существующий сервис. |
