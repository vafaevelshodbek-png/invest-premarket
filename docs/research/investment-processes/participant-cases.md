<a name="bonds"></a>

## Инвестор сравнивает облигации

| Поле | Содержание |
|---|---|
| Область | Облигации, вторичная покупка без маржинального финансирования |
| Роль | Самостоятельный частный инвестор. Для профессионального сравнения нужен отдельный разбор работы аналитика |
| Ситуация | Появились деньги для вложения на определённый срок, рассматриваются несколько выпусков |
| Задача | Сопоставить даты, купонную формулу, амортизацию, оферты, риски и цену с целями. Отметить несопоставимые показатели и недостающие сведения |
| Текущий процесс | [Сбор сведений](details.md#p02), [оценка](details.md#p03), [выбор действия](details.md#p04) |
| Вход | Цель и горизонт, документы выпусков и их версии, котировки на сопоставимый момент, расходы и ограничения |
| Результат | Сравнение с источниками и датами, допущения и решение: выбранный выпуск с параметрами либо отказ от покупки |
| Получатель | Сам инвестор, затем обработчик поручения при решении купить |

**Предполагаемая цена ошибки:** неподходящий денежный поток или решение на несопоставимой доходности. Размер потерь и распространённость не установлены.

**Следующее основание:** недавний реальный выбор инвестора, исходные документы нескольких выпусков и объяснение окончательного решения. Оно покажет текущий способ сравнения, без заранее заданного приложения или AI.

<a name="disclosure"></a>

## Аналитик разбирает новое раскрытие

| Поле | Содержание |
|---|---|
| Область | Акции или облигации конкретного эмитента |
| Роль | Аналитик эмитента, работающий для управляющего |
| Ситуация | Опубликованы новые отчётность или условия выпуска, прежнее заключение может требовать пересмотра |
| Задача | Сопоставить новое сообщение с исходными документами, выделить подтверждённые изменения, пересчитать затронутые предпосылки и обозначить неопределённость |
| Текущий процесс | [Сбор сведений](details.md#p02), [оценка инструмента](details.md#p03), передача в [выбор действия](details.md#p04) |
| Вход | Новое раскрытие, прежняя версия, действующая аналитическая оценка, сведения о позиции и ограничениях |
| Результат | Записка: что изменилось, где это подтверждено, какие прежние выводы сохраняются или требуют пересмотра |
| Получатель | Управляющий портфелем. Решение о сделке остаётся отдельным действием |

**Предполагаемая цена ошибки:** пропуск существенного изменения или необоснованный пересмотр оценки.

**Следующее основание:** одно реальное раскрытие с предыдущим документом и созданной аналитиком запиской. Наличие публичных PDF само по себе не подтверждает потребность в новом инструменте.

<a name="portfolio"></a>

## Управляющий пересматривает портфель

| Поле | Содержание |
|---|---|
| Область | Портфель из нескольких инструментов, применимый договор управления |
| Роль | Управляющий портфелем, риск-менеджер даёт ограничения, аналитик готовит оценки |
| Ситуация | Изменились цены, потоки или цели, текущее распределение нужно сопоставить с ограничениями |
| Задача | Проверить позиции и цены, объяснить отклонение, сравнить доступные действия с учётом риска, ликвидности и расходов |
| Текущий процесс | [Состояние портфеля](details.md#p14), [оценка риска](details.md#s01), [выбор действия](details.md#p04) |
| Вход | Сверенные позиции и потоки на дату, цены с датами, цели или мандат, ограничения, оценки вариантов |
| Результат | Зафиксированное решение с обоснованием и параметрами либо решение сохранить портфель |
| Получатель | Специалист исполнения при необходимости операции, риск-менеджер для контроля ограничений |

**Предполагаемая цена ошибки:** действие на неверной позиции или выход за ограничения. Стандарт доверительного управления не переносится автоматически на все виды фондов.

**Следующее основание:** обезличенный пример пересмотра, ограничения и фактическое решение, включая рассмотренный вариант ничего не менять.

<a name="execution"></a>

## Трейдер сопровождает частичное исполнение

| Поле | Содержание |
|---|---|
| Область | Вторичная торговля бумагой через брокера |
| Роль | Трейдер исполнения или специалист брокера по исключениям. Частный трейдер может сам контролировать своё поручение |
| Ситуация | Принятое поручение исполнено частично, остаются объём и срок действия |
| Задача | Сопоставить поручение, заявки и сделки, установить текущий остаток и статус. Дальнейшие действия сверить с условиями и полномочиями |
| Текущий процесс | [Приём поручения](details.md#p05), [исполнение и статусы](details.md#p07), затем [оценка качества исполнения](details.md#p23) |
| Вход | Условия поручения, история статусов, сделки с временем и объёмом, доступные рыночные данные |
| Результат | Согласованная исполненная часть, остаток и актуальный статус. Отдельно фиксируется основание изменения или отмены |
| Получатель | Клиент, специалист внутреннего учёта, расчётный специалист по заключённым сделкам |

**Предполагаемая цена ошибки:** повторная операция или неверное понимание остатка. Исполненное поручение не доказывает зачисление актива.

**Следующее основание:** обезличенная история одного частично исполненного поручения с итоговым состоянием. Изменять реальные заявки для исследования не требуется.

<a name="corporate-action"></a>

## Специалист передаёт корпоративную инструкцию

| Поле | Содержание |
|---|---|
| Область | Бумага с добровольным корпоративным действием, например выкупом |
| Роль | Специалист корпоративных действий у посредника. Решение принимает владелец или уполномоченный управляющий |
| Ситуация | Получено уведомление с вариантами участия и сроком подачи инструкции |
| Задача | Проверить применимость к позиции и сроки своего звена, получить решение уполномоченного лица, передать корректную инструкцию и отследить статус |
| Текущий процесс | [Волеизъявление](details.md#p18), данные [учёта прав](details.md#p11), последующие движения по применимости |
| Вход | Уведомление и его версия, подтверждённые права, варианты, крайние сроки, решение владельца и полномочия |
| Результат | Связанная с событием инструкция, подтверждение приёма либо отказ с причиной, затем статус участия |
| Получатель | Следующее звено учётной цепочки, владелец или управляющий получает подтверждения |

**Предполагаемая цена ошибки:** пропуск возможности участия или передача неверного волеизъявления. Срок посредника может отличаться от срока эмитента.

**Следующее основание:** публичное уведомление и обезличенная цепочка инструкции с подтверждениями. По одному календарю нельзя установить успешное участие.

<a name="payment"></a>

## Поддержка выясняет статус купона

| Поле | Содержание |
|---|---|
| Область | Выплаты по облигации |
| Роль | Специалист поддержки брокера. Специалист выплат или учёта подтверждает операционные сведения |
| Ситуация | Клиент сообщает, что ожидаемый купон не появился на счёте |
| Задача | Идентифицировать выпуск и событие, проверить право клиента, ожидание и фактические записи, установить, какой информации не хватает, направить вопрос профильному исполнителю |
| Текущий процесс | [Обращения](details.md#s10), [выплаты](details.md#p17), [клиентский отчёт](details.md#p21), при расхождении [сверка](details.md#p13) |
| Вход | Обращение, уведомление о событии, применимые позиции и документы по выплате, записи счёта, сведения об удержаниях при необходимости |
| Результат | Обоснованный ответ с подтверждённым статусом, источниками и следующим действием. Неизвестный статус явно остаётся неизвестным |
| Получатель | Клиент, а при необходимости специалист выплат или сверки получает конкретное расхождение |

**Предполагаемая цена ошибки:** ложное объяснение, неверное ожидание клиента или пропущенная операционная проблема. Календарь выплаты не подтверждает фактическое поступление.

**Следующее основание:** обезличенный закрытый случай с окончательной причиной и документами. Без клиентских записей доступен только разбор условий события, а не установление статуса выплаты.

<a name="reconciliation"></a>

## Специалист разбирает расхождение записей

| Поле | Содержание |
|---|---|
| Область | Учёт операций брокера или управляющего |
| Роль | Специалист сверки. Специалист внутреннего учёта или источник внешней записи участвует в исправлении |
| Ситуация | Количество бумаги или сумма в регистре не совпала с внешней выпиской |
| Задача | Сравнить записи на одинаковую дату и в одинаковом составе, связать операции по основаниям, отличить срок отражения от пропуска, дубликата или иной ошибки |
| Текущий процесс | [Сверка](details.md#p13), использующая [внутренний учёт](details.md#p12) и [учёт прав](details.md#p11) |
| Вход | Внутренний регистр, внешняя выписка или отчёт, даты и идентификаторы, первичные документы и статусы операций |
| Результат | Совпавшие записи и список расхождений с основаниями. Для закрытого расхождения сохраняются причина, разрешённое исправление и повторная сверка |
| Получатель | Уполномоченный исполнитель исправления, затем специалисты клиентской, бухгалтерской или внешней отчётности |

**Предполагаемая цена ошибки:** неверный остаток, повторная корректировка или неверный последующий отчёт. Электронный мэтчинг инструкций до расчёта является другой ситуацией, он не заменяет эту сверку.

**Следующее основание:** две обезличенные выгрузки и известная причина хотя бы одного расхождения. Автоматическое исправление без основания не является успешным результатом.

<a name="collateral"></a>

## Казначей покрывает потребность в обеспечении

| Поле | Содержание |
|---|---|
| Область | Участник клиринга с открытыми обязательствами, денежный рынок или производные |
| Роль | Казначей участника. Специалист контроля обеспечения определяет дефицит, расчётный специалист проводит движение |
| Ситуация | Получено маржинальное требование либо выявлена предстоящая потребность в деньгах или допустимом обеспечении |
| Задача | Проверить сумму, срок и допустимые активы, сопоставить доступные ресурсы и обязательства, организовать выбранное покрытие и получить подтверждение |
| Текущий процесс | [Контроль обеспечения](details.md#s02), [фондирование](details.md#p15), [движение активов](details.md#p10) |
| Вход | Требование для соответствующего участника, лимиты, календарь расчётов, доступные активы, ограничения и стоимость вариантов |
| Результат | План покрытия, распоряжения и подтверждённые движения либо зафиксированная непокрытая потребность с эскалацией |
| Получатель | Расчётный специалист, специалист контроля обеспечения и уполномоченный руководитель при дефиците |

**Предполагаемая цена ошибки:** непокрытое обязательство или излишние расходы на финансирование. Условия НКЦ не выдаются за условия маржинального обслуживания розничного клиента.

**Следующее основание:** обезличенное требование и история его покрытия в одной конкретной модели. Сумма дефицита, крайний срок и фактические расходы подтверждаются документами.

<a name="fund-redemption"></a>

## Специалист фонда сопровождает погашение пая

| Поле | Содержание |
|---|---|
| Область | Погашение паёв выбранного открытого ПИФ по его правилам |
| Роль | Специалист операций с паями в УК или у агента. Расчёт стоимости, контроль, реестровые записи и выплата выполняются соответствующими участниками |
| Ситуация | Через предусмотренный канал поступила заявка владельца на погашение |
| Задача | Связать заявку с владельцем и правилами фонда, проверить комплект и статус, получить применимую оценку, проследить записи и выплату в своей зоне ответственности |
| Текущий процесс | [Операции с паями](details.md#p25), [оценка имущества](details.md#p24), [контроль спецдепозитария](details.md#s07), расчёты и учёт прав по применимости |
| Вход | Заявка и полномочия, правила фонда, сведения о паях, расчётная стоимость на применимую дату, сообщения и расчётные документы |
| Результат | Цепочка статусов заявки, подтверждённое погашение и выплата компенсации либо отказ с основанием |
| Получатель | Пайщик, специалисты регистратора, депозитария, расчётов и учёта в соответствующих звеньях |

**Предполагаемая цена ошибки:** неверная сумма компенсации или потерянный статус заявки. Расчётная стоимость не заменяется биржевой ценой, погашение не считается вторичной продажей.

**Следующее основание:** правила конкретного фонда и обезличенная законченная цепочка одной заявки. Общая схема Платформы ПИФ не устанавливает штат и сроки выбранной УК.

<a name="data-quality"></a>

## Владелец данных разбирает неверную цену

| Поле | Содержание |
|---|---|
| Область | Данные для оценки портфеля, торговые и справочные источники |
| Роль | Владелец данных и специалист качества совместно с потребителем. Инженер данных устраняет техническую причину, если она выявлена |
| Ситуация | Проверка обнаружила пропущенную, устаревшую или неоднозначно сопоставленную цену |
| Задача | Установить источник, момент и идентификатор, проверить правило пригодности, определить затронутые расчёты, согласовать исправление и проверить результат |
| Текущий процесс | [Качество данных](details.md#s12), [снабжение данными](details.md#s11), затронутая [оценка портфеля](details.md#p14) |
| Вход | Данные и метаданные, исходная запись, правило качества, журнал загрузки, сведения о потребителях и расчётах |
| Результат | Подтверждённый дефект или допустимое состояние, решение о пригодности, основание исправления и статус повторной проверки затронутого результата |
| Получатель | Аналитик или риск-менеджер, владелец затронутого процесса, инженер исправления |

**Предполагаемая цена ошибки:** искажённая оценка или контрольный показатель. Отсутствие сделки по неликвидному инструменту само по себе не доказывает сбой загрузки, доступный API не гарантирует пригодность цены.

**Следующее основание:** один документированный инцидент с правилом качества и итоговым решением потребителя. Рекомендованная Банком России модель ролей уточняется по организации.
