## Примеры форматов и ограничения

<a name="f01"></a>

### F01. Bloomberg ASKB

[Официальная страница](https://professional.bloomberg.com/products/bloomberg-terminal/ai/askb/), разделы Integrated workflows, Personalized Lists и ASKB Drive. Прочитано: диалог внутри Terminal связан с рабочими списками и внутренним контентом с учётом разрешений. Пример используется для объяснения встроенного помощника в ситуации 2. Полнота поддержки конкретной модели аналитика не проверена. Вариант нашей панели является предложением, не описанием ASKB.

<a name="f02"></a>

### F02. Aladdin Copilot

[Официальная страница](https://www.blackrock.com/aladdin/platforms/products/aladdin-copilot), Key features и ограничения. Прочитано: ответы внутри платформы зависят от прав, область ограничена Aladdin. Это основание учитывать контекст и разрешения встроенного формата в ситуациях 3 и 11. Наличие продукта не подтверждает доступ нашей команды и пригодность нашей модели работы.

<a name="f03"></a>

### F03. Morgan Stanley Debrief

[Объявление о запуске](https://www.morganstanley.com/press-releases/ai-at-morgan-stanley-debrief-launch/). Прочитано: с согласия клиента создаются заметки встречи, действия и проект письма, который советник редактирует и отправляет, запись сохраняется в Salesforce. Это пример связи помощника, проверки человеком и рабочего дела. Применён как аналогия в ситуации 6. Проверка выплаты купона этим продуктом не подтверждена. Отзывы об экономии времени не использованы.

<a name="f04"></a>

### F04. T-Invest MCP и принятое исследование №30

Стартовая ссылка задачи: [T-Invest MCP](https://developer.tbank.ru/invest/mcp). Для выводов переиспользован принятый [раздел №30](../invest-api/reference.md#mcp) и [план проверки manifest](../invest-api/reference.md#handoff). Стартовая веб-страница не выдаётся за повторно прочитанную в этой работе. Подключение и список инструментов конкретного сервера не получены. MCP рассматривается как возможный способ интеграции помощника, а не готовый экран, регламент подтверждения или самостоятельный формат продукта.

<a name="f05"></a>

### F05. НРД: WEB-кабинет корпоративных действий

[Официальное описание](https://www.nsd.ru/workflow/system/programs/web-kabinet-kd/). Прочитано: интерактивное электронное взаимодействие и консолидация сведений по действию. Пример для ситуации 5 показывает уже существующее рабочее место. Встраивание нашей панели, расширение кабинета и полный набор проверок инструкций не подтверждены.

<a name="f06"></a>

### F06. НРД: Платформа ПИФ

[Официальное описание каналов](https://www.nsd.ru/faq/156-fz/), разделы о взаимодействии УК и WEB-кабинете/WEB-сервисе. Прочитано: интерактивный канал и отправка структурированных сообщений из собственного ПО являются разными способами работы. Использовано в ситуации 9. Поддержка интерфейса конкретного фонда и готовый коннектор нашей команды не установлены. Описание канала не означает успешное погашение или выплату.

<a name="f07"></a>

### F07. 1С-Рарус:Паевые инвестиционные фонды

[Официальное описание](https://rarus.ru/1c-upravlenie-nfo-mfo/1c-rarus-pif-2/), перечень операций и аналитических отчётов. Прочитано: операции с паями, проблемные заявки и отчёты по СЧА уже включены в существующий продукт. Пример для ситуаций 9 и 15. Возможность нашего расширения и установленная конфигурация не проверены, соответствие конкретному фонду не утверждается.

<a name="f08"></a>

### F08. Smart Collateral: интерфейс через MCP

[Объявление от 15 сентября 2026 года](https://smart.stream/de/press/smartstream-ermoeglicht-collateral-teams-mit-neuen-mcp-servern-sofortige-antworten-und-kontrollierte-automatisierung/), официальная немецкая версия. Прочитано: отдельно описаны чтение отчётной базы, использование API и включаемые действия. Использовано в ситуации 8 как пример разделения данных и полномочий. Не установлены российские подключения и фактический manifest. Готовность аналогичного формата у команды не заявлена.

<a name="f09"></a>

### F09. Prometheus: оповещения

[Официальные рекомендации](https://prometheus.io/docs/practices/alerting/), разделы What to alert on и Offline processing. Прочитано: оповещение должно помогать найти затронутый компонент, для обработки данных важна задержка. Пример для ситуации 14. Контроль технического сигнала не подтверждает восстановление финансовых записей, поэтому в предлагаемом формате сохраняется отдельная операционная приёмка.

<a name="f10"></a>

### F10. НРД: электронный мэтчинг

[Официальное описание](https://www.nsd.ru/services/depozitariy/operatsii-s-tsennymi-bumagami/vnebirzhevye-raschety/elektronnyy-metching/), прочитано при подготовке №32 в этот же день и использовано повторно. Подтверждает уведомления о потенциальных встречных инструкциях в описанном режиме. В ситуации 16 это основание использовать существующий канал и разбирать основание исправления. Обзор не подтверждает возможность встроить стороннюю панель или автоматически менять условия сделки.

## Что остаётся непроверенным

Для всех вариантов неизвестны фактический интерфейс выбранной организации, её права, частота задач, объём ошибок, бюджет и готовность сотрудников менять работу. Проверки в карточках адресуют конкретный пробел формата. Обязательность всех систем и предлагаемых подтверждений для всех участников рынка не утверждается.

LLM, RAG, MCP и API как технический транспорт не подменяют результат пользователя. API считается форматом продукта только там, где определён другой сервис как получатель результата и описано его следующее действие. Применение AI отдельно рассматривается в №22.
