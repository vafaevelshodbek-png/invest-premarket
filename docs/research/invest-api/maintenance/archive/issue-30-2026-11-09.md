## Выполненное решение: возможности API, MCP и ограничения среды

### 1. Основные выводы для выбора идеи

1. Документированы справочник инструментов, исторические и текущие рыночные данные, портфель, операции, события выплат, аналитика, заявки и тестовый контур. Наличие метода не подтверждает полноту данных конкретного инструмента или доступ конкретного пользователя. [S01], [S07], [S11], [S12], [S15], [S19]
2. T-Invest MCP дает агенту доступ к инструментам брокерской инфраструктуры. Состав и схемы конкретных tools нужно получить после подключения. Нельзя автоматически переносить названия и весь набор методов API в перечень MCP-tools. [S21], [S24]
3. Для новостей есть критичное ограничение: метод News предоставляет историю только за 24 часа. Для ретроспективных экспериментов потребуется отдельный разрешенный архив или собственный предварительный сбор. [S08]
4. Фундаментальные показатели покрывают не все активы. В соответствующем ответе ноль может означать отсутствие данных. Обновление обычно происходит на следующий рабочий день, но иногда задерживается более недели. [S08]
5. Sandbox подходит для проверки интеграции и последовательности действий. Его упрощения не позволяют подтверждать реальную исполнимость, ликвидность и доходность стратегии, налоговые и дивидендные сценарии. Есть расхождение между общей страницей и релизом 1.51, описанное ниже. [S17], [S18], [S20]
6. В переданном тексте первого отбора разрешены собственные модели, облака и внешние API. Обязательность MCP для SIGNAL IN не установлена в этой формулировке. В правилах следующих этапов роль MCP указана отдельно, требования этапов не смешиваем. [S25], [S26]

### 3. Подключение, форматы и обновление данных

**API.** Доступны gRPC, gRPC-web, REST и WebSocket. gRPC использует protobuf-контракты, REST и WebSocket предоставляют JSON-представление. REST-прокси не подменяет потоковую подписку, для событий выбирается поддерживаемый потоковый транспорт. [S02], [S32]

| Контур | gRPC | REST | MCP |
|---|---|---|---|
| Реальный | invest-public-api.tbank.ru:443 | https://invest-public-api.tbank.ru/rest/ | https://invest-public-api.tbank.ru/mcp |
| Песочница | sandbox-invest-public-api.tbank.ru:443 | https://sandbox-invest-public-api.tbank.ru/rest/ | https://sandbox-invest-public-api.tbank.ru/mcp |

Адреса подтверждены [S02], [S21], [S22]. В этом исследовании к ним не подключались.

**Денежные значения.** В контрактах используются MoneyValue с валютой и Quotation без валюты, с частями units и nano. В JSON int64-поля могут передаваться строками. Даты запрашиваемых периодов задаются по UTC. Конвертацию типов и проверку единиц нужно делать в коде. [S10], [S13], [S23]

**История свечей.** Параметры ниже - ориентиры из текущего контракта для **одного запроса**, а не обещание наличия такой истории у каждой бумаги. [S10]

| Интервал | Указанный максимальный период | Максимальный limit |
|---|---|---|
| 1 минута | 1 день | 2400 |
| 5 минут | 1 неделя | 2400 |
| 1 час | 3 месяца | 2400 |
| 1 день | 6 лет | 2400 |

Контракт также описывает другие интервалы. Даты начала минутной и дневной истории можно определить по first_1min_candle_date и first_1day_candle_date в справочнике. Длинный период может потребовать нескольких запросов и проверки пропусков. [S09], [S10]

Для истории операций предпочтителен GetOperationsByCursor. Старый GetOperations возвращает только последнюю тысячу операций, поэтому его нельзя считать полной исторической выгрузкой. [S28]

**Обновление.** Новости читаются постранично внутри доступного окна. Портфель и заявки можно получать запросами или потоками. Для точного наблюдения исполнения предпочтителен OrderStateStream, история операций приходит позднее. Сервисы не следует считать единым атомарным снимком. [S08], [S12], [S15], [S27]

Полный архив новостей, исторических стаканов и всех старых прогнозов для point-in-time теста этим исследованием не подтвержден. Их доступность проверяется отдельно под кандидата в #19. Это неизвестность, а не утверждение об отсутствии таких данных у Банка.

### 4. Лимиты и частота

Номинальные значения на странице лимитов на дату исследования: [S05]

| Группа | Лимит unary-запросов |
|---|---|
| Котировки | 600 в минуту |
| Инструменты, общий лимит сервиса | 200 в минуту |
| Перечисленные в документации методы каталогов, включая Shares, Bonds, Etfs | 15 в минуту |
| Операции | 200 в минуту |
| Песочница | 200 в минуту |

Это не универсальные лимиты любого метода. Есть исключения и динамическая политика, лимиты действуют совместно для счетов пользователя. Для текущих значений используются GetUserTariff и служебные заголовки ответа. [S05], [S06]

В документации указаны 32 рыночных соединения и суммарно 300 подписок на свечи, стаканы и сделки в одном рыночном потоке. Для свечей и стаканов предусмотрен интервал отправки 100 мс по подписке. Это ограничения доставки, а не измеренная задержка или гарантия пропускной способности нашей системы. [S05]

Лимиты самого MCP и расход серверных вызовов одним tool-вызовом отдельно не установлены. Оценка квот, задержек и стоимости цепочки агентных вызовов остается проверкой будущего сценария.

### 5. Доступ и безопасность

- Нужны брокерский счет, идентификация и действующий токен. Данные API названы бесплатными в вводной документации, но это не отменяет расходов на торговые операции, облака, хранение и LLM. [S01]
- Read-only предназначен для получения информации и не разрешает выставление торговых поручений. Full-access дает торговые возможности. Transfer-access дополнительно относится к переводам. Можно ограничить доступ одним счетом, кроме оговоренных в документации типов счетов. Sandbox использует свой вид токена. [S03]
- Токен сохраняется при выпуске. В документации указан срок три месяца с последнего использования и необходимость первого использования в течение семи дней. Порядок отзыва и перевыпуска нужно учитывать при проверке доступа. [S03]
- Для MCP в примере используется Authorization: Bearer и Streamable HTTP. Нужна корректная проверка TLS с доверенными сертификатами, обход проверки сертификатов не является решением ошибки подключения. [S04], [S22]
- Секреты хранятся вне репозитория и текста запросов к модели. Торговый токен способен разрешить действия без отдельного диалога с человеком. Подтверждение, лимиты и журнал действий реализуются в клиенте. В статье приведено хранение секретов в окружении или credentials и подтверждение через Telegram. [S22]
- Документацию T-API для бизнеса нельзя использовать как доказательство правил T-Invest. В частности, схемы авторизации и тестового доступа разных продуктов не взаимозаменяемы. Используем источники в разделе /invest/. [S02], [S03], [S04]

Рекомендации команды для следующей проверки: минимальные права, явный выбор sandbox, разрешенный перечень инструментов агента, маскирование данных в логах, таймауты и проверки денежных значений кодом. Веб-страницы и новости считать входными данными, не инструкциями для агента. Это предлагаемые меры продукта, а не проверенные здесь встроенные гарантии MCP. Спецификация MCP предусматривает проверку входов и контроля доступа, а для чувствительных действий рекомендует подтверждение пользователем. [S24]

### 6. Песочница: что именно можно и нельзя заключить

Документированы виртуальные счета, пополнение и операции с поручениями. Они отделены от реальных счетов. Для проверки интеграции доступны также sandbox-методы стоп-заявок. [S17], [S19]

Общая страница указывает: [S17]

- дивиденды и купоны на счет не начисляются, налоги не рассчитываются
- комиссия упрощена до 0,05% от сделки
- рыночное исполнение привязано к последней цене, заявки не воздействуют на рынок
- часть показателей портфеля и рисков не рассчитывается или упрощена

Таблица различий контуров отдельно исключает содержательные GetBrokerReport и GetDividendsForeignIssuer. Следовательно, sandbox не заменяет источник для проверки реальных налоговых отчетов и учета выплат. [S18]

**Расхождение документации.** Общая страница описывает упрощенное плечо и отдельные нулевые маржинальные показатели. При этом релиз 1.51 сообщает о расчете вариационной маржи, корректировке доступных лотов и запрете маржинальной торговли по некоторым инструментам. Реальную модель текущего sandbox по этим параметрам считать неизвестной до проверки конкретного инструмента. [S17], [S20]

Для первого отбора это означает, что sandbox обосновывает возможность технического теста. Он не доказывает экономический результат стратегии, доступность инструмента на реальном счете и качество исполнения при ограниченной ликвидности.

### 7. Собственные модели, облака и внешние API

Поле 8 первого отбора разрешает собственные модели, облака и API. В поле 7 описывается предполагаемая архитектура, дополнительный прототип не обязателен. Поэтому на SIGNAL IN достаточно обоснованного доступного контура и плана проверки, развертывание инфраструктуры для этой задачи не требуется. Источник требований - переданный текст формы, сохраненный в Wiki, а не самостоятельно выведенное условие. [S25]

Python и другие языки с SDK перечислены в документации API. Наличие SDK не заменяет проверку совместимости актуального контракта и сетевого окружения. [S01], [S04]

Для будущего MVP отдельно проверить: доступность выбранного LLM-провайдера для команды, стоимость и задержки, обработку передаваемых данных и права на используемые модели, датасеты и компоненты. Условия программы о правах на результаты и сторонние компоненты относятся к выбору зависимостей. Разрешение облаков не подтверждает соответствие любой сторонней лицензии этим условиям. [S26]

### 8. Непроверенные условия и передача в #19

Следующие пункты являются **планом**, их выполнение не заявляется:

| Проверка | Какое подтверждение требуется | Значение для выбора кандидата |
|---|---|---|
| Доступ команды | Права и область действия sandbox/read-only токена без публикации секрета | Отделить доступный источник от документированного |
| MCP manifest | tools/list со всеми страницами, именами и схемами, затем только безопасные read-only вызовы | Не выдумывать tool и его аргументы, проверить набор после подключения [S24] |
| Данные выбранных бумаг | Небольшие обезличенные ответы, начало истории, пропуски, даты публикации и обновления | Определить полноту и пригодность данных |
| Соответствие sandbox задаче | Таблица нужных полей и отказов против реального требования | Исключить ложную проверку налогов, выплат и исполнимости |
| Нагрузка | Квоты, задержка, размер ответов, поведение при ошибках и переподключении | Проверить выполнимость частоты обновления |
| Условия использования | Разрешения на хранение, передачу облаку и распространение нужных данных и компонентов | Установить ограничения конкретного продукта |

Готово для [#19](https://github.com/vafaevelshodbek-png/invest-premarket/issues/19): для каждого кандидата выбрать нужные строки матрицы и присвоить доступность «доступно», «условно доступно» или «неизвестно». Новостной ретротест, учет реальных налогов/выплат в sandbox, восстановление исторического стакана и предположение о полном совпадении API с MCP требуют отдельного основания. Идея и архитектура этой работой не выбирались.
